# dast-ng report — client-deliverable build plan

Status: **design locked, build not started.** Turns the current dark, screen-first technical
report into a **client-grade deliverable** that replaces the Burp Suite Enterprise report for
the client (and any client). Light, print/PDF-ready, self-contained, zero new dependencies.

Separate track from the console (that stayed dark/screen). The console is the operator tool;
the **report is the client artifact**. They share `report.VULN_META` + the store, nothing else.

## Locked decisions
- **Audience: client deliverable.** Light, professional, print-first. Cover page, executive
  summary, scope/methodology, findings, appendix.
- **PDF: print-optimized HTML.** A real `@media print` stylesheet (`@page` margins, page
  breaks, page numbers); operator does Cmd-P → Save as PDF. No headless-Chrome/WeasyPrint
  dependency — stays pure-Python + self-contained HTML, matching the appliance ethos.
- **No grade** (unchanged rule) — severity distribution + plain-language posture, never a
  letter/scorecard.
- **Self-contained** — one HTML file, inline CSS, embedded assets (logo as data-URI). Opens
  offline, prints clean.

## Benchmark: Burp "Scan Remediation Report #3223" (the bar to clear)
Its structure, section by section (what we match + beat):
- Cover: title, "Generated by … / date", **site name, scan window (start/end/duration/status),
  start URLs, reference #**.
- **Issues by severity** (H/M/L/Info + total) and **scan statistics** (discovered/audited URLs,
  requests made, network errors).
- **Issue index**: grouped by issue type with instance counts (e.g. "Open redirection [4]"),
  location, severity, confidence, jump-link.
- Per issue: **Issue detail** (instance-specific), **Issue background** (generic), **Issue
  remediation** (detailed), **References**, **Vulnerability classifications** (CWE list +
  CAPEC), **Request/Response**.

We already beat it on proof (we show the FULL request/response attack sequence + repro curl);
we're behind on cover/metadata, index+grouping, references, richer classifications, and the
client-ready light presentation. This plan closes those.

## Core principle: maximum detail — everything collected is displayed
Every field the pipeline captured for a finding appears in its detail: instance reasoning,
the exact payload, detection method + confidence, verification verdict + note, the FULL
request/response attack sequence (every exchange, not a sample), raw tool output, the repro
curl, CWE/CAPEC/OWASP classifications, authoritative references, and remediation — plus which
crawled URL it landed on. Nothing collected is summarized away or hidden behind "…". Long
blobs are shown in full (scrollable on screen; complete in print). This depth is the product's
differentiator over a shallow commercial scan.

## Report structure (client deliverable)
1. **Cover page** — client/org name + logo, report title, target(s)/scope, engagement window,
   prepared-by, date, reference id, confidentiality notice.
2. **Executive summary** — plain-language posture (count-based, no grade), severity
   distribution chart (inline SVG), headline risks, what was tested in one paragraph.
3. **Scope & methodology** — targets, authentication approach, tools/engines exercised,
   active-scan authorization, testing window, and honest limitations.
4. **Findings summary (index/TOC)** — grouped by issue type with instance counts, severity,
   confidence, and anchor links to each detail.
5. **Detailed findings** — grouped by type; per instance: location, issue detail (instance),
   background (generic), proof (request/response), remediation, references, classifications
   (CWE/CAPEC/OWASP), reproduce.
6. **Appendix** — tool roster + versions, engine health, coverage/scan statistics, glossary.

## Design direction (light, professional, print-first)
- Clean light ground; a restrained accent (deep slate/indigo), semantic severity colors kept
  legible on white and in grayscale print. Refined type: a strong system serif for headings +
  system sans for body (no webfont fetch — self-contained). Generous whitespace, ~65-char
  measure, tabular figures for stats.
- `@media print`: `@page { margin }`, page numbers via CSS counters, `break-inside: avoid` on
  finding cards + proof panes, repeated section context, cover + each major section start on a
  fresh page. Screen view is the same document, just not paginated.
- Severity/status encoded in form + color (stripe, pill) so it survives B/W printing.

## Content + data work
- **VULN_META enrichment** (18 categories): add `references` (authoritative links — OWASP,
  CWE, PortSwigger Web Security Academy) and richer `classifications` (primary CWE + related
  CWEs + CAPEC + OWASP). Optional CVSS vector/score per category (decide in R1).
- **Report metadata input** — a `report_meta` object (client name, logo path/data-URI, scope,
  engagement window, prepared-by, reference id, confidentiality text) via CLI flags
  (`--client`, `--window`, `--prepared-by`, `--logo`, `--ref`) and/or `--report-meta meta.json`.
  Sensible defaults; never fabricated.
- **Data-gap honesty** — dast-ng's engagement result does not yet capture scan start/end/
  duration, requests-made, or network-error counts (Burp does). R5 adds lightweight capture
  where cheap (timing, request counter); anything not captured is simply omitted, never faked.

## Phasing
- **R1 — Content model + enrichment. ✅ DONE.** `_CLASSES` (CWE/CAPEC chains) + `_REFS`
  (OWASP/PortSwigger/HHS links) for all 18 categories; `_meta_for` merges them. `report_meta`
  schema + CLI flags (`--client/--scope/--window/--prepared-by/--ref/--logo/--when`).
- **R2 — Light theme + document skeleton. ✅ DONE.** New light print-first CSS (serif heads +
  system sans, slate/indigo accent, grayscale-legible severity), gradient cover page, section
  scaffold, `@media print` (@page A4 margins, page-break-before per section, break-inside:avoid
  on findings/proof/blocks, light pre blocks for print). Chrome supplies print page numbers.
- **R3 — Executive summary + scope/methodology. ✅ DONE.** Count-based narrative (no grade),
  severity donut + CSS severity bars, scope & methodology table + session-health/limitations
  callouts.
- **R4 — Findings: grouping + index + MAX detail. ✅ DONE.** Grouped by issue type; index/TOC
  with anchors + instance counts; per-instance detail renders EVERYTHING collected — description,
  issue detail (reasoning), classifications (param + OWASP + CWE/CAPEC chips + detecting tool),
  payload, full request/response proof (every exchange), raw tool output (collapsible),
  reproduce curl, references, remediation; verified/detection/confidence badges.
- **R5 — Appendix. ✅ DONE.** Coverage stat cards, engine-health table (ran/missing/skipped +
  note), coverage-gap warning, about-this-report. (Scan timing / requests-made not yet captured
  engagement-side — omitted, not faked; a small future engagement add.)
- **R6 — Polish + print QA. ✅ CORE DONE.** Browser-verified structure (cover + 5 sections, 68
  grouped findings, all detail blocks, no horizontal overflow, no grade/scorecard). CLI
  `dast-ng report <json|scan-id --from-db> --client … -o out.html`. Deferred as minor:
  confidentiality watermark, engagement-side timing capture, console /api/report client-meta
  query params.
